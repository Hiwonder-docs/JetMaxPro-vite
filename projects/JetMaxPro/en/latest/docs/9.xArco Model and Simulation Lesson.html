9. xArco Model and Simulation Lesson ​

9.1 Lesson 1 Introduction to Xarco Model ​

xacro model is an expansion of URDF model. Actually, they are the same.

The Unified Robotic Description Format (URDF) is an XML file format, universal description format, used in ROS to describe all elements of a robot. Robots are usually composed of several linkages and joints that connect two linkages. A robot motion model is that multiple linkages are connected and restricted by each other. And UDRF files describe the relationship between joints and linkages, and their inertial properties, geometric characteristics and collision models.

9.1.1 Difference between URDF Model and Xacro Model ​

URDF model is a simple robot model description file whose structure is clear and easy to understand. But if you use URDF model to describe the robot that has complicate structure, the description file will be too long.

xacro model can fix this problem. xacro model can simplify robot description file in an advanced way, and increase reuse of codes.

For example, if you need to describes legs of humanoid robot, you need describe two legs separately when using URDF model. However, you just need to describe one leg and reuse this description when you use xacro model

9.1.3 Basic Parameters of URDF Model ​

XML Basic Syntax ​

As URDF model is based on XML format, you need to get basic understanding of XML format.

Element:

You can define element names as you want, but you need to follow the following rules.

<element>

</element>

Attribute:

Attribute is contained in element, which is used to define nature and parameters of an element. Element is defined following the rules below.

<element

attribute_1 = “attribute1”

attribute_2 = “attribute2”>

</element>

Comment:

Comment does not affect other attributes and elements. The syntax of comment is as follow.

<！-- comment>

Link ​

In URDF model, link describes the appearance and physical properties of a rigid component.

< visual >：describe the appearance parameters of link, including size, color, shape, etc.

< inertial>：describe inertial parameters of link containing dynamics operation of the robot.

<collision>：describes the collision properties of link.

Each tag has its own sub-tag and function. The following table shows functions of tags.

TagFunction
originDescribe link pose. xyz: describe the pose of link in simulated map. rpy: describe the posture of link in simulated map.
messdescribe the quality of link
inertiaDescribe the inertia of the link. Due to the symmetry of the inertia matrix, six parameters ixx, ixy, ixz, iyy, iyz, izz need to be filled in as attributes. These parameters can be obtained through calculation.
geometryDescribe the shape of the link. It uses mesh parameter to load the texture file, and the filename parameter to load the path address of the texture. There are also three sub-tags: box, cylinder, and sphere.
materialDescribe the material of link. Name parameter is indispensable. Color and transparency can be adjusted by sub-tag color

Joint ​

In URDF, joint describes the properties of joint kinematics and dynamics, and the position and speed restriction of joint movement.

Following tags are used to edit joint movements.

<parent_link>：parent link

<child_link>：child link

<calibration>：calibrate joint angle

<dynamics>：describe physical attributes of movements

<limit>： describes the limiting values of movement

Each tag has its own sub-tag and function. The following table shows functions of tags.

TagFunction
originDescribe link pose. xyz: describe the pose of link in simulated map. rpy: describe the posture of link in simulated map.
axisSet child link to rotate around any axis of parent link
limitLimit child link. Lower and upper attributes restrict the rotation range in radian. Effort attribute limits the force range during rotation. (value can be positive and negative and its unit is N) Velocity attribute limits rotation speed in m/s
mimicDescribe the relationship between this joint and other joints
safety_controllerDescribe safety controller parameters used to protect robot’s joints.

Robot Tag ​

Picture below shows the complete robot tag. <link> and <joint> tags must be included in <robot>.

Gazebo Tag ​

This tag combines with gazebo simulator to set some simulation parameters. You can use this tag to introduce gazebo plug-in, gazebo physical attribute settings, etc.

Write Simple URDF Model ​

Set Robot Model Name

Before writing URDF model, you need to set the robot model name, “<robot name=“ABC”>”. Input ‘</robot>’ at the end, which indicates you finish writing robot model

Set Link

  1. When writing the first link, use indentation to indicate that this link belongs to the model set up this time, and then you need to set the name of the link: "<link name="name">". At the end, you need to input "</link>", which means the writing is completed.

  2. When writing the link description part, use indentation to indicate that this description is used in the link. You need to enter "<visual>" to start the description, and enter "</visual>" to end the description.

  3. "<geometry>" is the description of the shape of link. You need to enter "</geometry>" to end the description, and the indentation indicate that the inside is a specific description of the shape of the link. The figure below describes the shape of a link: "<cylinder length="0.01" radius="0.2"/>".

  4. "<origin>" is the description of link position, and the indentation indicates the specific description of link position. The figure below describes link position: "<origin rpy="0 0 0" xyz="0 0 0" />". rpy is the angle of link, and xyz is the coordinate of link. It means that the link is at the origin of coordinate system.

  5. "<material>" describes link material. Indentation indicates the specific description of link color. You need to enter "<material>" to start the description, and enter "</material>” to end the description. Figure below shows that link color is set to yellow: "<color rgba="1 1 0 1" />". rgba="1 1 0 1" is the set color threshold.

Set Joint

  1. When writing the first joint, use indentation to indicate that this joint belongs to the model set this time, and then you need to set the name and type of the joint: "<joint name="name" type="joint type">". At the end, you need to enter "</joint>" to complete writing.

    Note: for type of joints, please check ‘4.2 joint’.

  2. When writing the first joint, use indentation to indicate that this description is used in the joint. You need to set parent parameter and child parameter in this format, “<parent link=“AB”/>”, “<child link=“AB” />”. The joint will rotate child link with parent link as fulcrum.

  3. "<origin>" is the description of joint position, and the indentation indicates the specific description of joint position. The figure below describes joint position: "<origin xyz=“0 0 0.1” />". xyz is the coordinate of joint.

  4. <axis> describes joint position, and the indentation indicates the specific description of joint posture. <axis xyz=“0 0 1” /> describes a joint posture, and xyz is coordinate of the set joint posture.

  5. “<limit>” limits joint movement, and indentation indicates the specific description of joint angle limit. Effort = ‘joint force (N)’, velocity = ‘joint motion speed’, lower = ‘radian lower limit’, upper = ‘radian upper limit’

  6. ‘<dynamics>’ describes joint dynamics, and indentation indicates the specific description of joint dynamics. damping=“damping value”、friction=“friction”。

9.4 Lesson 4 Introduction to Gazebo ​

Gazebo brings a fresh approach to simulation with a complete toolbox of development libraries and cloud services to make simulation easy. Iterate fast on your new physical designs in realistic environments with high fidelity sensors streams. Test control strategies in safety, and take advantage of simulation in continuous integration tests.

Usage:

● Test robotic algorithm

● Design robot

● Regression testing with real-world scenarios

Features of Gazebo:

● Contain multiple physical engines

● Contain abundant robot model and environment libraries.

● Contain various sensors

● Convenient program design and simple interface

Advice from Gazebo official: It is better run Gazebo on Ubuntu or other Linux distributions. The computer you use must involve following stuffs.

● Dedicated GPU：Nvidia card runs well on Ubuntu

● Intel I5 CPU or other CPU at same level as Intel I5

● at least 500MB disk storage

● install the advanced version Ubuntu Trusty

9.4.1 Gazebo Architecture ​

Gazebo uses a distributed architecture with separate libraries for physics simulation, rendering, user interface, communication, and sensor generation. Additionally, gazebo provides two executable programs for running simulations

a server gzserver for simulating the physics, rendering, and sensors

a client gzclient that provides a graphical interface to visualize and interact with the simulation

The client and server communicate using the gazebo communication library.

Gazebo Master

This is essentially a topic name server. It provides name lookup, and topic management. A single master can handle multiple physics simulations, sensor generators, and GUIs.

● Communication Library

Dependencies: Protobuf and boost::ASIO

External API: Support communication with Gazebo nodes over named topics

Internal API: None

Advertised Topics: None

Subscribed Topics: None

This library is used by almost all subsequent libraries. It acts as the communication and transport mechanism for Gazebo. It currently supports only publish/subscribe, but it is possible to use RPC with minimal effort.

● Physics Library

Dependencies: Dynamics engine (with internal collision detection)

External API: Provides a simple and generic interface to physics simulation

Internal API: Defines a fundamental interface to the physics library for 3rd party dynamic engines.

The physics library provides a simple and generic interface to fundamental simulation components, including rigid bodies, collision shapes, and joints for representing articulation constraints. This interface has been integrated with four open-source physics engines: Open Dynamics Engine(ODE), Bullet, Simbody, Dynamic Animation and Robottics Toolkit(DART)。

A model described in the Simulation Description Format (SDF) using XML can be loaded by each of these physics engines. This provides access to different algorithm implementations and simulation features.

● Rendering Library

Dependencies: OGRE

External API: Allows for loading, initialization, and scene creation

Internal API: Store metadata for visualization, call the OGRE API for rendering.

The rendering library uses OGRE to provide a simple interface for rendering 3D scenes to both the GUI and sensor libraries. It includes lighting, textures, and sky simulation. It is possible to write plugins for the rendering engine.

● Sensor Generation

Dependencies: Rendering Library, Physics Library

External API: Provide functionality to initialize and run a set of sensors

Internal API: TBD

The sensor generation library implements all the various types of sensors, listens to world state updates from a physics simulator and produces output specified by the instantiated sensors.

● GUI

Dependencies: Rendering Library, Qt

External API: None

Internal API: None

The GUI library uses Qt to create graphical widgets for users to interact with the simulation. The user may control the flow of time by pausing or changing time step size via GUI widgets. The user may also modify the scene by adding, modifying, or removing models. Additionally there are some tools for visualizing and logging simulated sensor data.

9.4.2 Gazebo Coordinate System ​

Coordinate system is indispensable to analyze forward and inverse kinematics.

  1. World Coordinate System

    World Coordinate System is a static reference coordinate system on the “ground”, which will not change with time. “Ground” here does not refer to the real ground. Take JetMax for example. Place JetMax on the desktop. World coordinate system is built on the desktop.

  2. Robot Arm Base Coordinate System

    Robot Arm Base Coordinate System is also called Base Coordinate System which is defined on the base of robot arm. If there is only one robot arm, robot arm base coordinate system coincides with world coordinate system.

    This coordinate system obeys right-hand rule. Therefore, base servo is the origin, red axis is X axis, green axis is Y axis, and blue axis is Z axis.

  3. Joint Coordinate System

    Joint Coordinate System is defined at robot joint.

    This coordinate system also obeys right-hand rule. Therefore, pink cone is the origin, red axis is X axis, green axis is Y axis, and blue axis is Z axis.

    Pay attention quantity of joint coordinate system is not fixed, and it is determined by the quantity of robot joint.

    For more information, please move to official website, http://gazebosim.org/

9.6 Lesson 6 Gazebo Simulation and Motion Planning ​

Introduction to Kinematics ​

Kinematics is a subfield of physics, developed in classical mechanics, that describes and researches the motion of objects without considering the forces that cause them to move. Kinematics model is a tool to study the law object position and time change.

Introduction to Motion Planning ​

Motion Planning is a method to find a path between specific point A and B, which can meet the restricted condition. Restriction includes none-collision, shortest distance, smallest power consumption, etc. For example, plan a collision-free path for robot arm to let it pick the objects.

9.6.1 Load Gazebo Kinematics Model ​

  1. Import and open JetMax virtual machine according to ‘Lesson 2 Import JetMax Virtual Machine Disk’.

  2. Press ‘Ctrl+Alt+T’ to open terminal

  3. Input command ‘roslaunch jetmax_control_gazebo jetmax_pick.launch’ and press Enter to open Gazebo to load JetMax robot arm model. This model contains red block.

  4. Click ‘Camera->Orthographic’ in the menu bar to display the model

  5. Open a new terminal, and input command ‘rosrun jetmax_control_gazebo go_home.py’ and press Enter to reset robot model

  6. Input command ‘rosrun jetmax_control_gazebo moving.py’ and press Enter to control suction nozzle to work

  7. Input command ‘rosrun jetmax_control_gazebo simple_pick.py’ and press Enter to control robot arm to suck the red block.

9.6.2 Gazebo Motion Planning ​

  1. Input command ‘rosservice call /jetmax_control/inverse_kinematics’ and press ‘Tab’ key to complement the command. Fill in the coordinate, then you can control robot to move.

  2. Input command ‘rosservice call /jetmax_control/forward_kinematics’ and press ‘Tab’ key to complement the command. Fill in the coordinate and press Enter to control robot to move through servo angle in radian.
